# CommentAudit：一款 Typecho「本地规则 + AI 审核」插件

> 作者：羽忆  
> 作者站点：https://lizihao.com/  
> 项目仓库：https://github.com/RainReiki/CommentAudit  
> 当前版本：1.0.7<br>
> 发布日期：2026-11-21  
> 适用环境：Typecho 1.3.x、PHP 8.0+、MySQL / MariaDB

---

## 为什么写这个插件

独立博客的评论区很矛盾。

一方面，希望读者能自由交流；另一方面，又不想每天面对广告、引流、诈骗、辱骂和一堆无意义灌水。

Typecho 自带的评论审核只有“全部待审”或“全部放行”，很难兼顾体验和安全。

CommentAudit 想做的，是把审核拆成两层：

```text
本地规则先拦截明显垃圾
→ 剩下的交给 DeepSeek 结合文章上下文判断
→ 插件再结合信誉和阈值给出最终结果
```

AI 不是唯一决策者。  
它只是一个更懂上下文的审核员，最终仍由本地规则、信誉等级和站点策略共同决定。

---

## 它怎么工作

一条评论提交后，会依次经过：

### 1. 本地硬规则

- 明确违禁词
- IP 黑名单
- 邮箱黑名单
- 网址黑名单

命中后直接拒绝，不消耗 AI 调用。

### 2. 本地预检

- 重复评论
- 同一 IP 高频评论
- 链接数量异常
- 疑似敏感词

这些信号会作为风险参考，交给后续判断。

### 3. DeepSeek 审核

AI 会结合：

```text
评论内容
评论者昵称
文章标题
文章原文（最多 3000 字）
文章摘要
文章分类
文章标签
评论者信誉 / 链接数 / 频率等特征
```

返回：

```json
{
  "decision": "pass|review|block",
  "category": "normal|ad|fraud|porn|illegal|abuse|threat|hate|...",
  "severity": "low|medium|high",
  "on_topic": true,
  "faithful": true,
  "confidence": 0.90,
  "reason": "简短原因"
}
```

### 4. 最终决策

```text
AI pass    → 直接通过
AI review  → 待审
AI block   → 按置信度和信誉阈值拒绝或待审
```

AI 失败、超时、没有配置 Key 时：

```text
转待审，绝不自动放行
```

这是插件最基本的安全底线。

## 核心功能

### 本地规则

- 明确违禁词：命中直接拒绝
- 疑似敏感词：只作为 AI 参考信号
- 词表作用域：内容、昵称、邮箱、网址
- IP 黑名单：支持单个 IP 和 CIDR
- 邮箱黑名单：支持邮箱和 `*@domain.com`
- 网址黑名单：支持域名、子域名、URL 前缀

### 本地预检

- 同一 IP 高频评论限制
- 重复评论检测
- 链接数量软标记
- 新用户链接风控

### AI 审核

- DeepSeek `deepseek-flash`，可切换其他模型
- 结合文章标题、原文、摘要、分类、标签
- 输出 pass / review / block
- 输出类别、严重度、主题相关、忠实度、置信度
- AI 结果缓存，减少重复调用
- 失败熔断，避免连续超时拖慢评论

### 信誉体系

评论者信誉分为：

```text
新用户 → 普通用户 → 老访客 → 白名单
```

规则大致为：

- 新用户：通过 0 条
- 普通用户：通过 1–2 条
- 老访客：通过 ≥ 3 条，且 90 天内无 spam
- 白名单：管理员手动设置

信誉会影响 AI block 的阈值：

```text
新用户 0.70
普通用户 0.80
老访客 0.90
```

### 新用户首条评论

当前策略：

```text
AI 明确 pass → 直接通过
AI review / block / 命中本地规则 → 待审或拒绝
```

不再因为“新用户第一条”而额外卡审。

### 后台列表增强

可选开启原生评论列表增强：

- 显示审核结论
- 显示原因和信誉
- 显示 AI 置信度
- 快捷拉黑，并同步处理当前评论

拉黑操作会同时写入插件黑名单。

该功能默认关闭，不改 Typecho 核心文件。

## 后台界面

### 插件原生设置页

使用底部导航切换下列分组。页面一次显示一组，切换时保留已输入的内容，点击「保存设置」统一提交。

- **DeepSeek 连接**配置 API Key、模型、服务地址、超时、最大 token、SSL 验证和调试日志。
- **词表与匹配范围**管理明确违禁词、疑似敏感词和检查字段。
- **黑名单**管理 IP、邮箱和网址规则。
- **频率与链接**配置同一 IP 的评论频率与链接数量限制。
- **AI 审核阈值**配置新用户、普通用户和老访客的置信度阈值。

API Key 已配置时显示固定圆点。留空保存会保留现有 Key，输入新 Key 后保存即可替换。

### 评论审核面板

```text
概览
信誉管理
审核日志
高级设置
```

概览包含：

- 今日决策统计
- 运行状态
- 规则摘要
- 最近决策
- 一键测试连接

审核日志只保留：

```text
评论内容
评论者
审核状态
时间
详情
```

完整信息放在详情弹窗里：

- 邮箱 / IP
- 完整评论
- 审核原因
- AI 决策 / 类别 / 严重度
- AI 置信度
- AI 原因
- 主题相关 / 忠实
- 耗时 / tokens
- 评论 ID / 文章 ID
- 是否人工处理

「高级设置」集中管理原生评论列表增强、审核日志保留天数、新增 AI 缓存的有效期和缓存清理。

### NewAdmin 与移动端

- 适配 Typecho 默认后台和 NewAdmin 2.6.x 的桌面与移动端。
- 插件界面跟随 NewAdmin 的亮色或夜间模式，可即时切换。
- 审核日志和信誉列表在窄屏上改用卡片布局。

## 安装

1. 下载 [CommentAudit-1.0.7.zip](https://github.com/RainReiki/CommentAudit/releases/download/v1.0.7/CommentAudit-1.0.7.zip)；
2. 解压后把 `CommentAudit` 目录放到：

```text
usr/plugins/CommentAudit
```

3. 后台“控制台 → 插件”启用；
4. 打开“控制台 → 插件 → 评论审核 → 设置”；
5. 至少在“DeepSeek 连接”里填写 API Key；
6. 根据自己的站点内容配置本地规则和黑名单；
7. 进入“管理 → 评论审核”查看概览、信誉和日志。

升级时用安装包内的 `CommentAudit` 目录覆盖原插件目录，已有配置和审核数据可继续使用。建议升级前备份数据库。

## 配置建议

### 明确违禁词

放真正违法、明显广告、诈骗、色情、赌博、辱骂等词。

不要把站点正常话题词放进去，例如：

```text
苹果、iPhone、Mac、Typecho、WordPress、插件、主题、
服务器、VPS、域名、备案、eSIM、流量卡、宽带、银行卡、信用卡
```

这些词在独立博客里很常见，放进去会造成大量误杀。

### 疑似敏感词

放广告、引流、金融、博彩、破解、翻墙等风险词。

它们只作为 AI 的参考信号，不会直接拒绝。

### IP 黑名单

建议先留空。

IP 黑名单应该来自你自己的垃圾评论日志，而不是从文章内容推测。  
先观察 3–7 天，再把真实垃圾 IP 加进去。

### 网址黑名单

可以先使用 TLD 级兜底：

```text
*.bet
*.casino
*.porn
*.xxx
*.adult
*.sex
*.cam
```

如果发现误伤，删除对应 TLD，改用具体域名或 URL 前缀。

## 隐私与安全

- API Key 只保存在站点插件配置中，不写入插件源码；
- 评论内容、昵称、文章标题、文章原文、摘要和审核特征会发送给 DeepSeek；
- 邮箱和 IP 不发送给 AI，只用于本地黑名单和频率判断；
- 生产环境请开启 SSL 验证；
- 调试日志默认关闭，仅在排障时开启；
- AI 失败时评论转待审，不会自动公开。

如果站点对隐私要求较高，可以只使用本地规则，不配置 DeepSeek Key。  
此时所有未命中本地规则的评论都会转待审。

## 已知限制

- AI 置信度是模型自评，不是严格校准的概率；
- 文章原文最多传入 3000 字，超长文章只取前 3000 字；
- AI 调用是同步的，平均耗时约 2 秒；
- 高并发场景尚未做专门压测；
- AI 对边界文本的判断可能存在波动，建议上线后先观察日志；
- 本地规则和黑名单需要根据站点实际垃圾评论持续调整。
