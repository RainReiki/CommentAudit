## 为什么写这个插件

独立博客的评论区很矛盾。

一方面，希望读者能自由交流；另一方面，又不想每天面对广告、引流、诈骗、辱骂和一堆无意义灌水。

Typecho 自带的评论审核只有“全部待审”或“全部放行”，很难兼顾体验和安全。

CommentAudit 想做的，是把审核拆成两层：

```text
本地规则先拦截明显垃圾
→ 剩下的交给 DeepSeek 结合文章上下文判断
→ 插件再结合信誉和阈值给出最终结果
```

AI 不是唯一决策者。  
它只是一个更懂上下文的审核员，最终仍由本地规则、信誉等级和站点策略共同决定。

## 它怎么工作

一条评论提交后，会依次经过：

### 1. 本地硬规则

- 明确违禁词
- IP 黑名单
- 邮箱黑名单
- 网址黑名单

命中后直接拒绝，不消耗 AI 调用。

### 2. 本地预检

- 同一评论者 7 天内的重复评论（直接拒绝）
- 同一 IP 高频评论
- 链接数量异常
- 疑似敏感词

重复评论直接拒绝，其余信号作为风险参考，交给后续判断。

### 3. DeepSeek 审核

AI 会结合：

```text
评论内容
评论者昵称
文章标题
文章原文（一级最多 2000 字，回复最多 800 字）
文章摘要
文章分类
文章标签
评论者信誉 / 链接数 / 频率等特征
```

返回：

```json
{
  "decision": "pass|review|block",
  "category": "normal|ad|fraud|porn|illegal|abuse|threat|hate|...",
  "severity": "low|medium|high",
  "on_topic": true,
  "faithful": true,
  "confidence": 0.90,
  "reason": "简短原因"
}
```

### 4. 最终决策

```text
AI pass    → 直接通过
AI pass + 身份中风险 → 待审
AI pass + 身份高风险（≥6 分）→ 拒绝
AI review  → 待审
AI block   → 按置信度和信誉阈值拒绝或待审
```

身份检查以 AI 为主：AI 结合昵称、邮箱前缀与域名、网址域名与是否首页、站点身份和历史组合，给出 0-10 分；本地只保留占位邮箱、IP 网址、异常编码等客观检查，不再维护品牌、平台、搜索引擎等大名单。最终分取两者较高值：3–5 分转待审，达到 6 分直接拒绝；AI 自身失败时只转待审。

AI 失败、超时、没有配置 Key 时：

```text
转待审，绝不自动放行
```

这是插件最基本的安全底线。

## 核心功能

### 本地规则

- 明确违禁词：命中直接拒绝
- 疑似敏感词：只作为 AI 参考信号
- 词表作用域：内容、昵称、邮箱、网址
- IP 黑名单：支持单个 IP 和 CIDR
- 邮箱黑名单：支持邮箱和 `*@domain.com`
- 网址黑名单：支持域名、子域名、URL 前缀

### 本地预检

- 同一 IP 高频评论限制
- 同一评论者的重复评论检测
- 链接数量软标记
- 新用户链接风控
- AI 身份评分 + 本地客观检查（3–5 分待审，6 分以上拒绝）

### AI 审核

- OpenAI 兼容接口，支持 DeepSeek 官方和第三方中转站
- 默认 `deepseek-flash`，可切换其他模型
- 结合文章标题、原文、摘要、分类、标签
- 输出 pass / review / block
- 输出类别、严重度、主题相关、忠实度、置信度
- AI 结果缓存，减少重复调用
- 失败熔断，避免连续超时拖慢评论

### 信誉体系

评论者信誉分为：

```text
新用户 → 普通用户 → 老访客 → 白名单
```

规则大致为：

- 新用户：通过 0 条
- 普通用户：通过 1–2 条
- 老访客：通过 ≥ 3 条，且 90 天内无 spam
- 白名单：管理员手动设置

信誉会影响 AI block 的阈值：

```text
新用户 0.70
普通用户 0.80
老访客 0.90
```

### 新用户首条评论

当前策略：

```text
AI 明确 pass 且身份信息正常 → 直接通过
AI pass 但昵称、邮箱或网址存在风险组合 → 待审
AI review / block / 命中本地规则 → 待审或拒绝
```

不再因为“新用户第一条”而额外卡审。

### 后台列表增强

可选开启原生评论列表增强：

- 显示审核结论
- 显示原因和信誉
- 显示 AI 置信度
- 快捷拉黑，并同步处理当前评论

拉黑操作会同时写入插件黑名单。

该功能默认关闭，不改 Typecho 核心文件。

## 后台界面

### 插件原生设置页

使用底部导航切换下列分组。页面一次显示一组，切换时保留已输入的内容，点击「保存设置」统一提交。

- **DeepSeek 连接**配置 API Key、模型、服务地址、超时、最大 token、思考模式、SSL 验证和调试日志。
- **词表与匹配范围**管理明确违禁词、疑似敏感词和检查字段。
- **黑名单**管理 IP、邮箱和网址规则。
- **频率与链接**配置同一 IP 的评论频率与链接数量限制。
- **AI 审核阈值**配置新用户、普通用户和老访客的置信度阈值。

「AI 审核阈值」中的「自动检查身份信息」默认开启。DeepSeek 根据昵称、邮箱前缀与域名、网址域名与是否首页、站点身份和历史记录，用模型知识判断这组资料是否像灌水或冒用，给出 0–10 分；本地只保留占位邮箱、IP 网址、异常编码等客观检查。最终分取较高值：3–5 分转待审，达到 6 分直接拒绝；AI 自身失败时只转待审。

API Key 每个字符显示为一个圆点。输入新 Key 后保存即可替换，清空后保存会移除已保存的 Key。

### 评论审核面板

```text
概览
信誉管理
审核日志
历史扫描
高级设置
```

概览包含：

- 今日决策统计
- 运行状态
- 规则摘要
- 最近决策
- 一键测试连接

审核日志只保留：

```text
评论内容
评论者
审核状态
时间
详情
```

完整信息放在详情弹窗里：

- 邮箱 / IP
- 完整评论
- 审核原因
- AI 决策 / 类别 / 严重度
- AI 置信度
- AI 原因
- 主题相关 / 忠实
- 耗时 / tokens
- 评论 ID / 文章 ID
- 是否人工处理

「高级设置」集中管理原生评论列表增强、审核日志保留天数、新增 AI 缓存的有效期和缓存清理。

「历史扫描」默认使用站内规则检查已通过的评论，也可选择 DeepSeek。扫描结束或暂停后，可以逐条处理，也可以勾选多条后打开「选中项」，标记为垃圾、转为待审核、直接删除或设为通过。

### NewAdmin 与移动端

- 适配 Typecho 默认后台和 NewAdmin 2.6.x 的桌面与移动端。
- 插件界面跟随 NewAdmin 的亮色或夜间模式，可即时切换。
- 审核日志和信誉列表在窄屏上改用卡片布局。

## 安装

1. 下载并解压 [CommentAudit-1.0.29.zip](https://github.com/RainReiki/CommentAudit/releases/download/v1.0.29/CommentAudit-1.0.29.zip)；
2. 解压后把 `CommentAudit` 目录放到：

```text
usr/plugins/CommentAudit
```

3. 后台“控制台 → 插件”启用；
4. 打开“控制台 → 插件 → 评论审核 → 设置”；
5. 至少在“DeepSeek 连接”里填写 API Key；
6. 根据自己的站点内容配置本地规则和黑名单；
7. 进入“管理 → 评论审核”查看概览、信誉和日志。

升级时用安装包内的 `CommentAudit` 目录覆盖原插件目录，已有配置和审核数据可继续使用。建议升级前备份数据库。

## 配置建议

### 明确违禁词

放真正违法、明显广告、诈骗、色情、赌博、辱骂等词。

不要把站点正常话题词放进去，例如：

```text
苹果、iPhone、Mac、Typecho、WordPress、插件、主题、
服务器、VPS、域名、备案、eSIM、流量卡、宽带、银行卡、信用卡
```

这些词在独立博客里很常见，放进去会造成大量误杀。

### 疑似敏感词

放广告、引流、金融、博彩、破解、翻墙等风险词。

它们只作为 AI 的参考信号，不会直接拒绝。

### IP 黑名单

建议先留空。

IP 黑名单应该来自你自己的垃圾评论日志，而不是从文章内容推测。  
先观察 3–7 天，再把真实垃圾 IP 加进去。

### 网址黑名单

可以先使用 TLD 级兜底：

```text
*.bet
*.casino
*.porn
*.xxx
*.adult
*.sex
*.cam
```

如果发现误伤，删除对应 TLD，改用具体域名或 URL 前缀。

## 令牌额度怎么填

后台「评论审核 → 设置 → API 额度」里的令牌额度是插件本地的熔断线，不是服务商账户余额。填 `0` 表示不限制。

一次审核大约消耗 **3,000–6,000 tokens**（包含文章上下文、提示词和模型输出）。建议：

- 额度 = 每月预计评论数 × 5,000 × 1.2
- 额外留 **20% 缓冲**，因为最后一次调用可能略超剩余额度
- 例：300 条/月 ≈ 1,800,000；1,000 条/月 ≈ 6,000,000
- 测试可先填 `100,000`；小站可用 `1,000,000–5,000,000`

周期可选每日 / 每月 / 累计。测试连接、历史扫描也会计入用量，命中缓存不计；如果中转站不返回 `usage.total_tokens`，额度不会累计。

## 隐私与安全

- API Key 只保存在站点插件配置中，不写入插件源码；
- 评论内容、昵称、文章标题、文章原文、摘要和审核特征会发送给 DeepSeek；回复评论还会附带最多六条上级对话中的昵称及正文摘要，用于理解正在回复的内容；
- 完整邮箱和 IP 不发送给 AI。开启身份检查时，还会发送邮箱前缀与域名、填写的网址域名与是否首页、站点名称与站长昵称，以及相关历史评论中的昵称、域名、邮箱是否相同和评论状态统计；不发送完整邮箱、网址路径或参数；
- 历史昵称、邮箱和网站组合只是访客填写的资料，不是已验证身份。没有历史记录、使用公共邮箱或填写第三方博客，本身不会被视为违规；本地身份规则也只依据这些填写内容，单项弱信号不会提高风险；
- 生产环境请开启 SSL 验证；
- 调试日志默认关闭，仅在排障时开启；
- AI 失败时评论转待审，不会自动公开。

如果站点对隐私要求较高，可以只使用本地规则，不配置 DeepSeek Key。  
此时所有未命中本地规则的评论都会转待审。

## 已知限制

- AI 置信度是模型自评，不是严格校准的概率；
- 一级评论最多传入 2000 字文章原文，回复最多传入 800 字；超长部分会被截断；
- AI 调用是同步的，平均耗时约 2 秒；
- 高并发场景尚未做专门压测；
- AI 对边界文本的判断可能存在波动，建议上线后先观察日志；
- AI 身份分基于模型知识和填写内容，不能真正核实域名归属，判断可能有波动；高风险会直接拒绝，建议上线后观察日志；
- 本地规则和黑名单需要根据站点实际垃圾评论持续调整。

## 更新记录

### 1.0.29

- **新增 API 令牌额度设置。** 后台「设置 → API 额度」可设置令牌额度和每日 / 每月 / 累计三种重置周期，0 表示不限制。
- **额度保护。** 达到额度后新评论自动转待审，不再调用 AI 接口；测试连接仍可手动执行。
- **用量显示。** 设置页显示当前周期已用、剩余、百分比和进度条，并附简单的填写建议。
- **统计范围。** 按服务商返回的 `usage.total_tokens` 统计评论审核、历史扫描和测试连接。

### 1.0.28

- **测试连接显示耗时。** 运行状态里的「测试连接」会在“连接正常”或失败原因后追加本次请求耗时，例如「连接正常 · 1845ms」，方便对比官方服务和第三方中转站。

### 1.0.27

- **连接设置顺序调整。** 依次为服务地址、API Key、模型、思考模式、请求超时、最大 token、SSL 验证、调试日志，先填地址和密钥再选模型。
- **模型列表改为下拉选择。** 获取后直接出现下拉框，选择即填入模型字段，不再依赖浏览器对 `datalist` 的支持；当前模型不在列表里时会保留为「当前」选项。

### 1.0.26

- **减少单次审核耗时。** 一级评论文章原文从 3000 字降到 2000 字，回复从 3000 字降到 800 字；上级对话正文和身份历史样本也做了更紧的截断，减少输入 token。
- **新增「思考模式」开关。** 中转站较慢、且支持 DeepSeek `thinking` 参数时，可在设置里选择「关闭思考」，通常能明显减少等待；如果中转站提示不支持该参数，改回「保持默认」即可。
- **建议同时调整最大 token。** 中转站较慢时可以把「最大 token 数」从 1200 降到 800；审核结果本身很短，一般够用。

### 1.0.25

- **设置页可获取模型列表。** 保存服务地址和 API Key 后，点击模型字段下方的「获取模型列表」，插件会读取当前服务的 `/models` 或 `/v1/models`，把可用模型 ID 填入候选，解决官方与中转站模型名不一致的问题。
- **兼容两种模型列表格式。** 支持 `data[].id` 和字符串数组，并在 `/v1/models` 与 `/models` 之间自动尝试。

### 1.0.24

- **支持第三方中转站。** 服务地址可填根地址、`.../v1` 或完整的 `.../v1/chat/completions`；根地址会依次尝试 `/v1/chat/completions` 和 `/chat/completions`，不再要求必须是 DeepSeek 官方地址。
- **兼容更多返回格式。** 支持中转站返回 SSE 流式数据、`content` 数组、`choices[0].text` 等格式，并自动跳过 BOM 或 JSON 前后的多余内容。
- **错误提示更具体。** 非 JSON 响应会显示 HTTP 状态、实际请求地址和返回片段，并提示检查 `/v1` 路径或中转站拦截，不再只提示“服务没有返回有效的 JSON”。

### 1.0.23

本版整合 1.0.18–1.0.23 的迭代。

- **身份检查改为 AI 评分。** AI 结合昵称、邮箱前缀与域名、网址域名与是否首页、站点身份和历史记录，输出 0–10 分；本地只保留占位邮箱、IP 网址、punycode、网址内嵌凭据等客观检查，不再维护品牌、平台、搜索引擎、短链接等大名单。最终分取较高值：3–5 分转待审，6 分及以上直接拒绝；AI 失败时只转待审。
- **身份详情显示分数和依据。** 审核详情会显示类似「高 · 身份组合不一致（7 分）」，历史扫描同步显示。
- **重复评论只按同一评论者判断，回看 7 天。** 有邮箱时按邮箱，没有邮箱时按昵称 + IP；同一文章下不同访客的相同内容不再算重复，同一评论者 7 天内完全相同的正文仍直接拒绝。
- **减少维护成本。** 身份判断主要交给 AI，本地只保留不需要外部知识的客观检查；提示词缓存版本同步更新，旧缓存自动失效。

### 1.0.17

- **回复会结合正在聊的话题审核。** 一级评论参考文章，二级、三级等回复优先参考父评论及所在分支的上级对话，最多读取六条。正常接话、道谢和话题延伸，不再仅因偏离文章主题而转待审。
- **审核依据更清楚。** 新评论和历史扫描都使用回复上下文，审核详情会显示实际参考的上级对话摘要。旧扫描结果需重新扫描才会采用新规则。
- **修复安装包权限。** 文件权限统一为 644，目录为 755，避免服务器无法读取插件文件而出现后台 500 / Server Error。已受影响的站点需修正现有文件权限，或使用本次安装包重新解压覆盖。

### 1.0.16

- 自动结合站点信息和相关历史评论，辅助识别昵称混淆、可疑身份组合，无需维护博友名单。
- 正文审核与身份检查分别显示。正文正常但身份存在疑点时，转为待审核；详情和历史扫描结果会显示依据。

### 1.0.15

在「控制台 → 插件 → 评论审核 → 设置」的底部新增「查看更新」，点击后会在新标签页打开 GitHub 仓库。

如果你从 **1.0.7** 直接升级，还会获得以下改进。

- **扫描历史评论。** 在「管理 → 评论审核 → 历史扫描」选择要检查的评论范围。可以只用本地规则，也可以加上 DeepSeek 复核。扫描支持暂停和继续。
- **直接在结果页处理评论。** 可逐条处理，也可勾选多条后通过「选中项」标记为垃圾、转为待审核、直接删除或设为通过。直接删除前会提示确认。批量处理成功后，页面会自动刷新并显示「已处理 X 条」。
- **API Key 按字符显示圆点。** 保存后，每个字符显示为一个 `•`。清空后保存会移除密钥，输入框保持空白。
- **DeepSeek 失败时会说明原因。** 连接测试和历史扫描会提示密钥无效、余额不足、请求超时或证书问题等具体原因。

### 1.0.14

- API Key 留空保存后显示为空。保存后的密钥每个字符显示一个圆点。

### 1.0.13

- 历史扫描结果的「选中项」提供标记为垃圾、转为待审核、直接删除和设为通过。直接删除前会提示无法撤销。

### 1.0.12

- 批量处理成功后自动刷新历史扫描页，显示「已处理 X 条」，可直接开始下一次扫描。

### 1.0.11

- 历史扫描时可以先全选，后续找到的待处理评论会一起勾选。暂停或完成后可以直接处理。
- 批量确认和处理进度显示在扫描页。请求超时后可以在同一页重试。

### 1.0.10

- 在历史扫描结果中逐条处理或跨页勾选后批量处理，可标为垃圾、转为待审核或设为通过。
- 可以按扫描建议批量处理，提交前会显示所选数量和操作方式。

### 1.0.9

- 历史扫描和连接测试会提示 DeepSeek 失败的具体原因，例如密钥未通过验证、余额不足、请求超时或证书问题。
- Windows 上使用 PHP cURL 时，可从系统读取信任的证书。官方 Flash 和 V4 Pro 模型使用非思考模式返回审核结果，减少等待和输出截断。

### 1.0.8

- 在「管理 → 评论审核 → 历史扫描」检查以前发布或待审的评论。可暂停和继续，结果仅在当前页面显示。
- 可以只用本地规则，也可以让 DeepSeek 复核。结果列出原状态与处理建议，由管理员决定是否处理。

### 1.0.7

- **设置一次只显示一组。** 用页面底部的按钮切换。可以先改词表，再改黑名单，最后点一次「保存设置」。
- **看到 `••••••••` 就表示已填写 DeepSeek 秘钥。** 想保留原来的密钥，直接保存即可。要更换时，输入新密钥再保存。

### 1.0.6

- **设置归到两个地方。** DeepSeek 和审核规则在「控制台 → 插件 → 评论审核 → 设置」。评论列表增强、日志保留天数和 AI 缓存在「管理 → 评论审核 → 高级设置」。
- **手机上更容易看审核记录。** 审核日志和访客信誉在窄屏上按条显示。电脑和手机都适配了 Typecho 默认后台，使用 NewAdmin 时会跟随亮色或夜间模式。
- **修好了几个后台问题。** 高级设置可以正常打开，筛选审核日志或搜索访客信誉后会留在对应页面。
